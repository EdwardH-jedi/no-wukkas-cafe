These tests assert the required corrected behaviour, not the defect, and contain no `skip`, `fails`, or
expected-crash inversion. The implementer must fix production code without editing these reviewer tests.

F1 has two red tests. They use the real app recorder, telemetry store, JSON export/parser and summariser:
checkpoint → later completion (real headless Day 2, six serves), and checkpoint → later trial quit at steam.
Both versions have the same record ID and distinct `endedAt` times. `[old, latest]` works;
`[latest, old]` does not. Preserve the newest record by its timestamp independently of file ordering;
do not sum snapshots of the same run. The test does not prescribe a policy for equal timestamps.

F2 has five red tests: unknown kind, null, incomplete shift, string `served`, and the CLI with a valid
sample followed by an invalid-record file. The last case currently exits **0**, emits no diagnostic and
prints a normal table with **3 sessions instead of 2**. Validate record shape and the fields consumed by
aggregation before returning `ok: true`; reject the input with its filename and no partial table.
The parser's current cast is not runtime validation. The tests leave wording and validation implementation open.

Two green independent controls verify pooled medians (`[1,2,3] + [100]` → **2.5 s**, not an average of
per-shift medians), exact-export deduplication and input immutability.
